# CCA exams implementation plan

[STATUS: APPROVED] — user approved GitHub Pages + separate API, ten exams and ten attempts per candidate per topic, then requested memory-only active answers, exit confirmation, summary-only browser storage and topic reset.

**Goal:** Add `/cca` using the site's existing components and semantic theme tokens, backed by a separate authenticated exam service.

**Architecture:** The static Next.js page calls a standalone Node HTTP API. SQLite persists verified identities, sessions, active attempts and compact results. The answer-bearing JSON stays outside the static export. Ten seeded forms cover every structurally usable question with balanced reuse, without repeats inside a form.

**Tech stack:** Existing React, TypeScript, Tailwind and Playwright; Node built-in HTTP, crypto, SQLite and test runner. No new packages.

## Contracts and decisions

- Topic IDs match sheet IDs: `cca-f`, `ccao-f`, `ccar-p`.
- CCA-F and CCAO-F have 60 questions; CCAR-P uses 63. All run for 120 minutes. Sources and the limit of simulated scoring are documented with deployment instructions.
- Exactly ten forms per topic. One use of each form per reset cycle, at most ten attempts. Start consumes the attempt; abandon/timeout also consumes it.
- Email OTP verifies identity; a server secret derives a stable pseudonymous candidate ID. Name, email, token, room code, question data and answers never enter browser storage.
- Room verification uses a salted scrypt hash from server environment. The static build receives only a public API URL. Production fails closed without required configuration and email delivery.
- An active attempt holds a temporary server snapshot and answers. Finalization is idempotent and removes both, preserving only aggregate results. Deadline checks precede mutations and a timer finalizes disconnected attempts.
- Browser `beforeunload` warns on reload/close. `pagehide`, confirmed internal navigation, explicit exit and unmount abandon the attempt best-effort. Cancellation keeps memory unchanged. Unreliable unload delivery cannot evade limits or restart a deadline.
- History uses at most 30 compact records per candidate; no per-question review is persisted. Storage failure does not prevent completing an exam.
- Topic reset requires room verification and a confirmation dialog. It removes only that candidate's selected topic attempts and restores ten uses; other topics are unaffected.
